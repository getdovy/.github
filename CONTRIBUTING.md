# Contributing

This applies to every getdovy repository without a guide of its own.
Recipes have theirs:
[dovy-catalog's CONTRIBUTING.md](https://github.com/getdovy/dovy-catalog/blob/main/CONTRIBUTING.md).

## Issues

Use the repository's issue forms; they ask for what is needed to act on
a report. Security problems are never reported in issues:
[SECURITY.md](SECURITY.md).

## Pull requests

- From a branch of your fork, into `main`.
- For anything larger than a fix, open an issue first, so the approach is
  agreed before the work.
- One change per pull request, with the tests it needs.
- A maintainer reviews and merges; automatic checks run on every pull
  request.

Commits follow [Conventional Commits](https://www.conventionalcommits.org/):
`type(scope): summary`, for example `fix(upgrade): keep the index`.

## Licence

By opening a pull request you agree that your contribution is licensed
under the repository's licence: GPL-3.0-or-later, or GPL-2.0-only for
dovy-kernel.

Everyone taking part follows the [code of conduct](CODE_OF_CONDUCT.md).
